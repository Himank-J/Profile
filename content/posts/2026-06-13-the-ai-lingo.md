## Foundation Layer

### 1. Token

**Definition**

A token is the basic unit of information processed by a language model. Models do not directly understand words or sentences; they first convert text into tokens and then operate on those tokens. A token may represent a complete word, part of a word, punctuation, or other text fragments.

**Why It Exists**

Language models operate on numerical representations rather than raw text. Tokens provide a consistent way to break language into smaller units that can be converted into numbers and processed by neural networks.

Every interaction with a language model ultimately involves tokens. They determine how much information can be processed, how much memory is consumed, how long inference takes, and how much a request costs.

**Key Concepts**

When interacting with an LLM, two types of tokens are important:

Input Tokens are all tokens sent to the model. These include system prompts, user messages, retrieved documents, conversation history, memory, and tool outputs.

Output Tokens are tokens generated by the model as part of its response.

Most AI providers price models based on token consumption. Input and output tokens are usually billed separately, with output tokens often costing more because the model generates them sequentially.

For example, if a request contains 2,000 input tokens and produces 500 output tokens, billing is typically calculated using both values.

**Common Misconceptions**

*Token ≠ Word*. One word may become multiple tokens, while some tokens may represent only part of a word.

*More Tokens = Better Results*. Supplying excessive information often increases cost and may introduce noise. Relevance usually matters more than volume.

### Context Window

**Definition**

The context window is the maximum amount of information a model can consider during a single interaction. It is measured in tokens and includes everything the model sees: system instructions, user messages, retrieved documents, tool outputs, memory, and conversation history.

**Why It Exists**

Language models do not have unlimited working memory. The context window defines the boundary of what the model can actively reason over at a given moment.

As AI applications evolved from simple chatbots to document assistants, coding copilots, and autonomous agents, larger context windows became increasingly important because models often need access to substantial amounts of information to perform effectively.

**Key Concepts**

A larger context window enables models to process longer documents, analyze larger codebases, maintain longer conversations, and work with more retrieved information.

However, larger context windows introduce tradeoffs. More context increases inference costs because additional tokens must be processed. It can also impact latency and, in some cases, reasoning quality. Models may become distracted by irrelevant information or fail to prioritize the most important details when excessive context is provided.

This is why modern AI systems focus not only on increasing context size but also on improving context quality through retrieval and context engineering techniques.

**Common Misconceptions**

*Larger Context Always Means Better Results.* In reality, relevance matters more than volume. A carefully selected 10,000-token context often outperforms a poorly curated 100,000-token context.

*Context Window Equals Memory.* The context window only represents what the model can currently see. It does not provide persistent memory across sessions.

**When It Matters**

Context windows become particularly important when working with long documents, enterprise knowledge bases, coding assistants, research applications, and agentic workflows that accumulate large amounts of information over time.

### Prompt Engineering

**Definition**

Prompt engineering is the practice of designing instructions that help a model generate reliable, useful, and consistent outputs. It focuses on how tasks are communicated to the model rather than how the model itself is trained.

**Why It Exists**

Language models are highly capable but inherently flexible. The same model can produce significantly different outputs depending on how a request is framed.

Prompt engineering emerged as a way to reduce ambiguity, improve consistency, and guide models toward desired behaviors without modifying the underlying model.

**Key Concepts**

A good prompt typically contains four elements:

* A clear objective describing the task.
* Relevant context needed to perform the task.
* Constraints that define rules or boundaries.
* An expected output format.

For example, asking a model to "summarize this document" may produce inconsistent results. Specifying the audience, desired length, and output structure generally produces much more reliable responses.

**Common Misconceptions**

*Prompt Engineering Is About Magic Phrases.* There is rarely a secret phrase that dramatically improves performance. Clarity and structure matter far more.

*Prompt Engineering Can Solve Every Problem.* Prompting can improve results, but it cannot compensate for missing knowledge, poor retrieval, or fundamental model limitations.

**When It Matters**

Prompt engineering is important whenever consistency, reliability, and structured outputs are required. It remains a foundational skill for anyone building AI applications, even as newer disciplines such as context engineering and agent engineering become increasingly important.

### Context Engineering

**Definition**

Context engineering is the practice of determining what information should be supplied to a model at runtime. While prompt engineering focuses on instructions, context engineering focuses on ensuring the model has access to the right information when making decisions.

**Why It Exists**

Modern AI systems rarely operate using prompts alone. They often rely on retrieved documents, user preferences, memory, database records, tool outputs, and conversation history.

The challenge is deciding which information should be included and which information should be excluded. Poor context selection is one of the most common causes of inaccurate, expensive, or unreliable AI systems.

**Key Concepts**

The primary goal of context engineering is relevance. The model should receive enough information to perform the task effectively, but not so much information that important signals become diluted.

Effective context engineering often involves:

* Selecting relevant documents.
* Filtering noisy information.
* Managing conversation history.
* Injecting memory when needed.
* Balancing cost and accuracy.

In many production systems, context engineering has a greater impact on quality than prompt engineering because even the best instructions cannot compensate for missing or irrelevant information.

**Common Misconceptions**

*Context Engineering Means Providing More Context.* The objective is not maximizing context volume but maximizing context quality.

*Context Engineering Is Just RAG.* RAG is one technique used to retrieve information. Context engineering is the broader discipline of deciding what information ultimately reaches the model.

Relationship to Other Terms

* Prompt Engineering defines how instructions are given.
* Context Engineering determines what information the model receives.

RAG, memory systems, retrieval pipelines, and knowledge sources are often components of a context engineering strategy.

### RAG (Retrieval-Augmented Generation)

**Definition**

Retrieval-Augmented Generation (RAG) is a technique that combines information retrieval with language generation. Instead of relying solely on knowledge stored within model parameters, a RAG system first retrieves relevant information from external sources and then uses that information to generate a response.

**Why It Exists**

Language models are trained on historical data and cannot continuously learn new information after deployment. Organizations, however, often need AI systems that can access frequently changing knowledge such as policies, documentation, customer records, contracts, or internal knowledge bases.

RAG solves this problem by separating knowledge from the model itself. Information can be updated in the knowledge source without retraining the model.

**Key Concepts**

A typical RAG workflow consists of three steps:

* Retrieve relevant information.
* Add retrieved information to the model's context.
* Generate a grounded response using that information.

RAG is most effective when knowledge changes frequently, when source attribution is important, or when retraining models is impractical.

Compared to fine-tuning, RAG is generally easier to update and maintain because new information can be made available immediately through retrieval.

**Common Misconceptions**

*RAG Eliminates Hallucinations.* RAG reduces hallucinations but cannot eliminate them. If retrieval returns poor or irrelevant information, the model can still generate incorrect responses.

*RAG Replaces Fine-Tuning.* RAG and fine-tuning solve different problems. RAG primarily adds knowledge, while fine-tuning primarily changes behavior.

**Relationship to Other Terms**

RAG commonly relies on embeddings, vector databases, retrieval systems, and context engineering techniques. Retrieved information is ultimately inserted into the model's context window before generation.

**When It Matters**

RAG is the preferred approach when building AI systems that need access to dynamic knowledge, enterprise documentation, customer-specific information, regulatory content, or any information that changes more frequently than model training cycles.

### 6. Embeddings

**Definition**

Embeddings are numerical vector representations of data that capture semantic meaning. They transform text, images, audio, or other data into a list of numbers that can be compared mathematically. The key idea is that items with similar meanings tend to have embeddings that are located close to each other in vector space.

**Why It Exists**

Traditional systems rely heavily on exact keyword matching. This works well when users use the same words as the source content, but it breaks down when different words express the same idea.

Embeddings allow systems to search and compare information based on meaning rather than exact wording. For example, a query about "vehicle insurance" can retrieve content discussing "car coverage" even though the words are different.

Key Concepts

Embeddings and tokens are often confused but serve very different purposes.

* Tokens are used by language models to process and generate text. Embeddings are used to measure similarity between pieces of information.
* When text is converted into embeddings, semantically related content tends to cluster together. This makes embeddings particularly useful for Semantic search, RAG systems, Recommendation systems, Clustering and categorization.

Embeddings are typically generated using specialized embedding models optimized for capturing meaning rather than generating text.

**Common Misconceptions**

*Embeddings Are Just Another Form of Tokens.* Tokens help models understand language during inference. Embeddings help systems compare meaning between pieces of data.

*Embeddings Understand Facts.* Embeddings capture semantic relationships, not factual correctness. Two factually incorrect statements can still have similar embeddings if they express similar ideas.

**When It Matters**

Embeddings are foundational to modern retrieval systems. Whenever an AI application needs to find related information, perform semantic search, or retrieve relevant knowledge, embeddings are usually involved somewhere in the architecture.

### 7. Vector Database

**Definition**

A vector database is a database designed to efficiently store, index, and search vector embeddings. It enables fast similarity searches across millions or even billions of vectors, making it a core component of many modern AI systems.

**Why It Exists**

Embeddings are useful only if they can be searched efficiently. Traditional databases excel at exact matches and structured queries but are not optimized for finding vectors that are mathematically similar.

Vector databases solve this problem by providing specialized indexing techniques that enable fast semantic search at scale.

**Key Concepts**

In a typical RAG system, documents are converted into embeddings and stored in a vector database. When a user submits a query, the query is also converted into an embedding. The database then identifies the most semantically similar vectors and returns the associated documents.

Despite the name, vector databases do not store only embeddings.

Most modern vector databases also store:

* Original document content
* Metadata
* Tags and filters
* Access control information
* Structured attributes

This allows applications to combine semantic search with traditional filtering. For example, a system might search for semantically similar documents while restricting results to a specific customer or document type.

**Common Misconceptions**

*Vector Databases Only Store Vectors.* In practice, metadata and associated content are equally important.

*Vector Databases Are Required for RAG.* RAG requires retrieval, but retrieval can be implemented using multiple approaches. Vector databases are simply the most common solution.

**When It Matters**

Vector databases become important whenever semantic search, large-scale retrieval, recommendation systems, or enterprise knowledge retrieval are involved. They are often one of the first infrastructure components introduced when moving from simple AI prototypes to production systems.

## Agent Layer

### 8. Agent

**Definition**

An agent is an AI system that can independently perform tasks by combining reasoning, planning, memory, and tool usage to achieve a goal. Unlike a traditional chatbot that primarily generates responses, an agent is designed to take actions.

**Why It Exists**

Many real-world tasks require more than answering questions. Tasks such as processing claims, booking travel, investigating incidents, or conducting research involve multiple steps, external systems, and decision-making.

Agents emerged as a way to extend language models beyond conversation and enable them to execute workflows.

**Key Concepts**

At the center of most agents is an LLM, but the agent itself includes additional capabilities such as:

* Goal management
* Planning
* Tool usage
* Memory
* Workflow execution

For example, a customer support agent may retrieve account information, search documentation, invoke backend APIs, and generate a final response. The language model provides reasoning capabilities, while the surrounding system enables action.

**Common Misconceptions**

*An Agent Is Just an LLM.* An LLM is typically one component of an agent. The agent includes the orchestration, tools, memory, and decision-making framework around the model.

*Any Chatbot Is an Agent.* A chatbot becomes an agent only when it can actively perform tasks rather than simply respond to prompts.

**Relationship to Other Terms**

* Agents often combine Tool Calling, Memory Layers, Orchestration, Guardrails, Context Engineering
* Many modern AI applications are effectively agents built around one or more language models.

**When It Matters**

Agents are most useful when tasks require multiple steps, access to external systems, dynamic decision-making, or autonomous execution rather than simple question answering.

### 9. Agentic AI

**Definition**

Agentic AI refers to AI systems that can autonomously decide how to achieve a goal rather than simply responding to individual requests. The defining characteristic is not the use of an agent architecture, but the presence of decision-making and action-taking capabilities.

**Why It Exists**

Traditional AI systems operate in a reactive manner. A user provides a prompt, and the model generates a response.

Many business problems, however, require AI systems to determine what actions to take, what information to gather, which tools to use, and how to sequence multiple steps toward an objective.

Agentic AI addresses this need by introducing autonomy into the workflow.

**Key Concepts**

An agentic system may:

Break a goal into sub-tasks.
Decide which tools to use.
Gather additional information.
Revise plans when conditions change.
Execute actions with minimal human intervention.

The emphasis is on goal completion rather than single-response generation.

Agentic AI exists on a spectrum. Some systems perform limited planning and tool usage, while others can execute complex workflows involving multiple agents and external services.

**Common Misconceptions**

*Agentic AI Means Fully Autonomous AI.* Most practical systems still operate within carefully defined boundaries and human oversight mechanisms.

*Agentic AI Is Just Tool Calling.* Tool calling enables actions, but agentic behavior requires decision-making about when and why those actions should occur.

**Relationship to Other Terms**

* An agent can exist without being highly agentic.
* Agentic AI describes the degree of autonomy a system exhibits when pursuing goals.
* The concepts of agents, orchestration, memory, planning, and tool usage are often closely connected within agentic systems.

**When It Matters**

Agentic AI becomes relevant when building systems that must complete tasks, coordinate workflows, interact with multiple systems, or operate with limited human supervision.

### 10. Tool Calling

**Definition**

Tool calling is the capability that allows a language model to invoke external functions, APIs, services, databases, or applications during execution. It enables models to interact with systems beyond their own training data and context window.

**Why It Exists**

Language models are excellent at generating text but cannot directly perform actions such as querying a database, checking the weather, sending an email, or retrieving live information.

Tool calling bridges this gap by allowing models to request the execution of external capabilities and then use the returned results to continue processing.

**Key Concepts**

A model does not directly execute tools. Instead, it identifies that a tool is needed, generates the appropriate structured request, and passes that request to the surrounding application.

Common examples include:

* Database lookups
* Search systems
* Calendar systems
* Custom business workflows

Tool calling is one of the most important advancements enabling AI systems to move from knowledge-based interactions toward action-oriented workflows.

**Common Misconceptions**

*Tool Calling Is Only Used by Agents.* Many non-agentic AI systems use tool calling. For example, a chatbot that retrieves live weather information may use tools without exhibiting agentic behavior.

*Tool Calling Makes Models Smarter.* Tool calling expands capabilities rather than intelligence. It gives models access to external information and actions but does not change the underlying reasoning ability of the model.

**Relationship to Other Terms**

- Tool calling is often a building block for Agents, Agentic AI, MCP, Skills and Orchestration frameworks
- Many modern AI systems rely heavily on tool calling even when they are not considered agents.

**When It Matters**

Tool calling becomes essential whenever AI systems need access to live data, enterprise systems, databases, external services, or actions that cannot be completed through text generation alone.

### 11. MCP (Model Context Protocol)
Definition

Model Context Protocol (MCP) is an open standard that allows AI models and applications to connect with external tools, data sources, and services through a consistent interface. Rather than building a custom integration for every application, MCP provides a common protocol that both AI systems and tool providers can understand.

Why It Exists

Before MCP, integrating AI systems with external tools often required custom code for every service. Connecting an AI application to a database, document repository, ticketing system, or internal platform meant building and maintaining separate integrations.

MCP was introduced to standardize this process. It allows tool providers to expose capabilities once and makes them accessible to any MCP-compatible client.

Key Concepts

MCP is not a tool itself. It is a communication standard.

An MCP server can expose:

Tools and actions
Documents and resources
Structured data
Enterprise systems

An MCP client can discover and interact with those capabilities without needing custom integration logic for each provider.

The primary benefit is interoperability. As MCP adoption grows, organizations can integrate new systems more quickly while reducing integration complexity.

Common Misconceptions

MCP Is a Replacement for APIs. MCP typically sits on top of existing systems and APIs. It standardizes how AI applications interact with them.

MCP Automatically Makes Systems Agentic. MCP provides access to capabilities. Whether a system behaves agentically depends on how those capabilities are used.

Relationship to Other Terms

MCP and Tool Calling are often confused.
- Tool Calling is the mechanism through which a model invokes a capability.
- MCP is a standardized way of exposing those capabilities.

A useful analogy is that tool calling is the conversation, while MCP defines the language spoken during that conversation.

When It Matters

MCP becomes valuable when integrating AI systems with multiple tools, enterprise applications, knowledge sources, or third-party services, especially in environments where interoperability and maintainability are important.

### 12. Skills
Definition

Skills are reusable capabilities that package specific functionality, instructions, tools, workflows, and domain knowledge into a unit that an AI system can invoke when needed. They allow AI applications to perform specialized tasks without embedding all logic directly into the main prompt or agent.

Why It Exists

As AI systems become more complex, placing every instruction, workflow, and tool inside a single agent quickly becomes difficult to manage.

Skills provide modularity. Instead of building one massive agent, developers can create focused capabilities such as "Document Summarization," "Claims Validation," or "SQL Analysis" and make them available when required.

Key Concepts

A skill typically combines:
- Purpose-specific instructions
- Tool access
- Domain knowledge
- Workflow logic
- Output formatting rules

Skills help reduce prompt complexity, improve maintainability, and encourage reuse across multiple applications.

Organizations often use skills to standardize common business functions while allowing different agents to leverage the same underlying capability.

Common Misconceptions

Skills and Tools Are the Same Thing. A tool usually performs a single action. A skill often combines multiple tools, instructions, and workflows into a higher-level capability.

Skills Replace Agents. Skills are often components used by agents rather than standalone replacements for them.

Relationship to Other Terms

Skills and MCP solve different problems.
- MCP standardizes access to capabilities.
- Skills package and organize capabilities into reusable business functions.

An agent may discover a capability through MCP and then use it as part of a skill-driven workflow.

When It Matters

Skills become increasingly important as organizations scale AI systems and need reusable, maintainable, and domain-specific capabilities that can be shared across multiple applications and agents.

## Model Optimization Layer

### 13. Fine-Tuning
Definition

Fine-tuning is the process of further training a pre-trained language model on additional data to modify its behavior, style, or task performance. Rather than training a model from scratch, fine-tuning starts with an existing foundation model and adapts it to specific requirements.

Why It Exists

Prompts and retrieval can provide additional information, but they cannot fundamentally change how a model behaves. Organizations sometimes need a model to consistently follow a particular style, perform specialized tasks, or understand domain-specific patterns.

Fine-tuning addresses this by embedding desired behaviors directly into the model's parameters.

Key Concepts

Fine-tuning is most effective when the goal is behavioral adaptation rather than knowledge injection.

Common use cases include:
- Structured information extraction
- Classification tasks
- Domain-specific writing styles
- Customer support workflows
- Specialized reasoning patterns

One of the key tradeoffs is training cost versus inference cost.

A fine-tuned model requires upfront investment in data preparation, training, evaluation, and deployment. However, once trained, it often requires shorter prompts and less contextual information, which can reduce inference costs over time.

Common Misconceptions

Fine-Tuning Is the Best Way to Add Knowledge. Frequently changing information is usually better handled through RAG.

Fine-Tuning Makes Models Instantly Better. Poor training data can degrade performance rather than improve it.

When It Matters

Fine-tuning becomes valuable when a behavior must be applied consistently across large volumes of requests and cannot be reliably achieved through prompting or retrieval alone.

### 14. Synthetic Data

Definition

Synthetic data is data generated artificially rather than collected from real-world human interactions. In AI systems, synthetic data is often produced by language models and then used for training, fine-tuning, evaluation, or data augmentation.

Why It Exists

High-quality training data is often expensive, scarce, sensitive, or difficult to obtain. Synthetic data helps address these challenges by generating additional examples that would otherwise require significant manual effort.

As modern models improve, synthetic data has become an increasingly important part of AI development pipelines.

Key Concepts

Synthetic data can be used to:
- Expand small datasets
- Generate edge cases
- Create instruction-following examples
- Produce evaluation datasets
- Improve class balance

It is particularly useful when organizations possess limited labeled data or when privacy concerns restrict the use of real-world information.

Many state-of-the-art models now rely on a combination of human-generated and synthetic data during training and post-training stages.

Common Misconceptions

Synthetic Data Is Always Lower Quality Than Human Data. High-quality synthetic data generated and reviewed properly can be extremely valuable.

More Synthetic Data Always Improves Models. Poor-quality synthetic data can introduce bias, amplify errors, and degrade performance.

When It Matters

Synthetic data becomes important when training data is limited, expensive, sensitive, or imbalanced. It is increasingly used in fine-tuning pipelines, evaluation systems, and domain adaptation workflows.

## Infrastructure Layer

## 15. Harness Engineering

Definition

Harness Engineering is the practice of designing and building the infrastructure layer that surrounds a language model in a production AI system. While models provide reasoning capabilities, the harness determines how those capabilities are used, controlled, monitored, and integrated into real-world applications.

Why It Exists

A language model alone is rarely sufficient for production use. Real applications require retrieval, memory, tool access, safety controls, observability, evaluation mechanisms, and workflow management.

Harness Engineering emerged from the realization that much of an AI system's reliability comes from the surrounding architecture rather than the model itself.

Key Concepts

A typical AI harness may include:

Prompt management
Context engineering
Tool integrations
Memory systems
Guardrails
Evaluation pipelines
Monitoring and observability
Routing and orchestration

The harness acts as the operational environment in which the model functions.

As models become increasingly capable, competitive advantage often shifts from model selection toward harness design.

Common Misconceptions

The Model Is the Product. In many production systems, the harness contributes more to reliability and business value than the model itself.

Harness Engineering Is Just Prompt Engineering. Prompts are only one component. Harness Engineering encompasses the broader architecture surrounding the model.

When It Matters

Harness Engineering becomes critical when moving from prototypes to production systems where reliability, governance, scalability, and maintainability are essential requirements.
